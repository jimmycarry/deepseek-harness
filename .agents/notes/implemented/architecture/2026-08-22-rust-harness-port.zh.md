# Agent Note: Rust harness 移植以 TypeScript 为行为真源

Status: implemented

[English](2026-08-22-rust-harness-port.md) | 中文

## Problem

第二种实现语言不能发明第二套产品。如果 Rust 树自造 loop、事件名或会话日志规则，之后每次改动都会有两个答案，也无法说明用户拿到的是哪一套。`packages/` 下的 TypeScript 树已经拥有这些名字：没有特权内核，正在运行的 `dsh` 就是由 profile、bundle 与 patch 层组装出来的 Cordis 插件树。

## Decision

`rust/` 是一个 Cargo workspace，移植同一棵插件树、同一组能力 seam 和同一套会话日志约定。crate 名为 `dsh-<pkg>`；目录对齐 `packages/<group>/<pkg>/`。TypeScript 仍是行为真源：Rust 侧若要偏离某个 TypeScript 名字或日志事件，必须先改 TypeScript 真源，否则不能落地。

工作区目标为 Rust 1.83 与 edition 2021。会拉入 edition 2024 或 `hashbrown` 0.17 的依赖在 lockfile 处拒绝。Loader YAML 是手写子集，不使用 `serde_yaml`，并解析 Include 方言：`- insert:` 列表、按 id 整字段替换、`inject`、`|` / `>-` 块、flow 序列，以及存成 `{ "__jsExpr" }` 的 `!!js`。HTTPS 提供方调用走 `curl`，不使用 `reqwest`；宿主 HTTP 监听器是手写 HTTP/1.1，不使用 `axum`。`Branded<B>` 手写 `Clone` 与 `Debug`，品牌标记类型因此不必实现这些 trait。

能力 seam 必须完整：Service Definition、Service Provider、Consumer。工具 Consumer 只依赖 Definition crate。随部署变化的值是构造时传入的 `Config` 字段；`run` 不隐藏默认值。模型可见内容必须记入日志；压缩用 `surfaceOp: replace` 推进 surface，不删除历史。会话日志保持 `SESSION_FORMAT_VERSION` `0`；SQLite 后端使用单调递增的 `SCHEMA_VERSION` `2`，并把会话 header 与事件行一并存储。未知且 required-on-read 的事件类型会拒绝 resume，除非信封带 `ignorable: true`。

两个自动化 stdio 服务器以 shipped profile 的形式落在同一棵 base 树上，由 `dsh-bundle-acp` 与 `dsh-bundle-jsonrpc` patch 层组合（`dsh --profile acp` / `dsh --profile jsonrpc`；两者都关掉 hmr 并在 `dsh-base` 之上插入各自的服务器行）。`dsh-acp` 以固定握手回答 `initialize`（`protocolVersion` 1、`deepseek-harness-acp` 0.0.1、image/audio/embeddedContext 全为 false、空 `authMethods`），`authenticate` 回答 `{}`,按 TypeScript 的 `Invalid params: <detail>` 文句校验 `session/new`（`cwd` 必须绝对路径;拒绝 `mcpServers` 与 `additionalDirectories`），只接纳文本 `session/prompt` 块并按类型给出精确拒绝文句，每个已提交的 assistant 文本块发出一条 `session/update` `agent_message_chunk`,并按 TypeScript 结算的 stop-reason 映射作答（`interrupted` → `cancelled`;`completed` / `max-tokens` / `aborted` / `blocked` → `end_turn`;`error` 结局以 `Internal error: turn failed: <message>` 拒绝）;`session/cancel` 是无 id 通知，未知方法回答 `"Method not found": <method>`（`-32601`）。`dsh-sdk-server` 保持线上稳定身份 `deepseek-harness-sdk-runtime`,校验 `initialize`（`maxTokens` 必须为正;缺适配器以 `no adapter registered for provider "<provider>"` 失败），按 `session/prompt` 的 `sessionId` 在 initialize 的 `cwd` 下惰性创建每会话一个 agent,投递前对照存活注册表复核记录，把该轮每个已记录事件以 `session.event` 流出并用 `session.status` `running` / `idle` 括起（入箱 splice 先于 `running`,与 TypeScript 通知顺序一致），并把该轮收集到的 `subagent.started` / `subagent.finished` 插在 `idle` 之前，回答 `messageId` 回执;`shutdown` 释放服务器所有的 agent 而上下文继续运行。TypeScript 服务器入队后由 agent 在后台运行、边跑边流;Rust 服务器在请求内把 turn 驱动到静止，所以回执落在通知之后的同一条有序 stdio 流上——通知顺序本身不变。`dsh-sdk-client` 在等待响应时跳过无 id 帧、按线序收集，并从最后一条已提交 `assistant/message` 投影 `finalResponse`;`dsh-webserver` 的 `/rpc` 路由以纯请求/响应提供同一协议。

## Alternatives considered

- **先把 loop 做成一个 `async fn`，以后再插件化** — TypeScript 规则正好相反：新行为落在已文档化的扩展点上。单体实现会丢掉 `agent/pre-step`、`agent/request`、`agent/request-error` 和 `agent/turn-stopping` 这些插件真正运行的位置。
- **用 Rust 重写 Web UI** — 宿主只需讲现有客户端协议。第二套 UI 是产品分叉，不是移植。
- **把压缩做进 loop** — TypeScript 压缩是 `agent/pre-step`、`agent/request-error` 与空闲 maintenance 的 Consumer。放进 `step` 会让之后每个引擎都变成 loop 改动。
- **把 Python SDK 当成第二套 loop** — 两个 SDK 都投影 TypeScript loop。再让 Rust loop 被这些 SDK 重实现，就会变成第三套驱动。
- **`serde_yaml` / `reqwest` / `axum`** — 各自会拉入 edition 2024 或 `hashbrown` 0.17 图，Rust 1.83 编不过。手写 YAML 子集、`curl` 传输和 HTTP/1.1 监听器把工作区钉在已声明的工具链上。
- **为旧磁盘格式做兼容垫片** — 预发布立场拒绝旧后端。垫片会把格式错误藏到第一次打 tag。

## Consequences

在打 tag 发布之前，仓库会同时带着两棵语言树。`rust/` 下的 `cargo test --workspace` 是 Rust 侧证据；无密钥 spine 快照在 `rust/apps/cli/tests/headless_snapshot.rs`，覆盖文本轮次、`bash` 轮次、用 `job_output` 收取的后台 `bash` 作业、`write` / `edit` TypeScript headless-profile 词表，包括这些编排与 spill 轮次、`session/title-llm-request` 载荷、工作区 `AGENTS.md` 基线（`user/message` 带 `source.kind: "agent-instructions"` 与 `<system-reminder>` 框）、对该文件后续 `write` 发布
