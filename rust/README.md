# DeepSeek Harness — Rust port

English | [中文](README.zh.md)

1:1 semantic port of the TypeScript harness. The TypeScript tree under `packages/` remains the behavior source of truth. This workspace preserves the plugin tree, capability seams, and session-log contract. Composition identity is the TypeScript row `id` plus plugin `name`; `dsh --dump-config` prints that composed tree. A task run mounts the same tree; `!!js` is evaluated only at mount. Session JSONL leads with the TypeScript header line and serializes every event — typed and Extension alike — as `{type, seq, time, data}` with `sourceEventSeqs` citations; messages carry `role` and a UUID `id`, and the TypeScript `StreamChunk` tags are preserved. Session titles run for real: the deterministic fallback plus a first-prompt LLM provider that logs `session/title-llm-request` before its auxiliary call. Headless mounts `bash-sandbox`, `job_output` / `job_list` / `job_kill` (`ctx.jobs`; bash `run_in_background` and one-shot subagent background return `started background job <id>`), `glob` / `grep` (ripgrep over `ctx.subprocess`), `str_replace_editor`, `create_goal` / `get_goal` / `update_goal`, continuable background `subagent` (the delegation requires `ctx.sessionPersistence` and returns a durable child id; a caller-reserved id is rejected when the live catalog or persistence already owns it; `send_message` / `interrupt_agent` / `list_agents` address it (`send_message` persist-loads a child absent from the live catalog, `list_agents` inspects that child (read-only, no `commitRepair`) and reports unreadables as `[diagnostic: corrupt|unavailable]` instead of dropping them; persistence `list_snapshots` / `read_stored_revision` expose a backend-owned revision token — JSONL uses the TypeScript file-stat identity, SQLite uses event-count plus header digest, and `inspect` shares in-flight loads, retries when that token changes, and keeps a ready LRU of `preparedSessionCacheSize` (default 5); `list` / `list_snapshots` still read the backend directly), the child-scoped `report` relays selected content to the direct parent, and a settlement notice wakes the parent with the child's outcome and closing message; in-process starts capture the parent's explicit sandbox override and pin approval to `never` as `source: "delegation"` events on the child log, and a cold resume replays those events) plus one-shot `subagent_fork`, `workflow` (`return <json>`), `ralph` (the TypeScript fixed fresh-agent loop in Rust over `spawn`; not a JavaScript worker), `/feedback` (`recordInput: false`; log-only `command/run` / `feedback/record` / `command/done`; the acknowledgement cites `$DSH_HOME/.anonymous-user-id` and the optional `ctx.sessionTelemetry` sharing sentence), `fs-observation-policy` (session-owned `fs/observed` records; `write` / `edit` / `str_replace_editor` take `createIfAbsent` or `replaceIfVersion` and refuse an unobserved overwrite with the TypeScript `FS_NOT_OBSERVED` sentence plus “read the file, then retry”), `web_search` (DeepSeek official or a `replay` fixture), `repeat-tool-reminder`, `ctx.attachments`, `ctx.sessionQuery` (`openAt: never`), spill (`ctx.spillStore` plus `spill-policy`), `todo_write` (log-only `todo/write`), the tool-call timeout policy (per-tool declared `timeout_ms`, `TOOL_TIMEOUT` failure text), the compaction-time tool-result pruner (`compaction/prune` plus a `tool/result` replace), plan mode (`plan/mode`, `exit_plan_mode`, `/plan`; headless has no user-questions provider so plan review fails with the exact sentence), the skill stack (`SKILL.md` discovery, the `skill` tool, the first `skill-catalog` message, and a later `update: true` replacement when the catalog digest changes), `ctx.tokenMeter`, settings-file (reload `$DSH_HOME/settings.yaml` after debounce; an invalid live edit keeps the last good document; `update` persists one registered namespace as a comment-preserving YAML leaf diff), `ctx.shellEnv` (trusted `DSH_HOME` / `DSH_SHELL=1` / `DSH_SESSION_ID` on model bash), compaction (`llm-deepseek` `defaultContextWindow` plus per-model catalog, default 1,000,000; `thresholdRatio` / `retainRatio` pressure against `ctx.llm.resolve_model_info().context.contextWindow`, exact `modelPolicies` overrides, a retain cut that snaps head-ward so tool-call/result pairs stay intact, pressure retries bounded by `compactionRetries`, overflow recovery that retries only after a durable surface replacement and stops at `maxOverflowRetries`, `ctx.llm.stream()` with `purpose: "compaction"` plus the TypeScript instruction and multi-block checkpoint frame, a framed checkpoint that must be smaller than the shadowed span, `compactionId`-carrying `compaction/start` / `summary` / `end` with `provider` / `model` / `rawOutput` / `llmStreamCall` on the summary, and `/compact` via `commands.execute` citing `command/done.sourceEventSeq`), `agent-instructions` (first `AGENTS.md` / `CLAUDE.md` plus `$DSH_HOME/AGENTS.md` baseline as a `<system-reminder>` `user/message` with `source.kind: agent-instructions`, plus a later non-baseline update when those files change), `session-checkpoint-policy` (flush before each model request and top-level tool dispatch; a missing persistence backend is a successful no-op; JSONL dispose drains live sessions), `ctx.sessionProjections` (`list_agents` fails with the TypeScript registry-missing sentence when that service is absent), and `llm-retry` (no Config; `retryPolicy` lives on each provider and is copied onto `agent/request-error`; `llm/retry` then `llm/retry-started` before the wait; a valid positive `providerRetryAfterMs` at or below `maxDelayMs` replaces local backoff, while an over-cap instruction makes `normal` delegate and `always` use local backoff). `llm-deepseek` classifies non-2xx responses with the TypeScript status and provider-detail codes and retains HTTP status, a valid positive `Retry-After` delay-seconds or HTTP-date, and `x-request-id` / `x-deepseek-request-id`. `llm-deepseek` resolves `DEEPSEEK_API_KEY` through `ctx.credentials` (inherited env, then `$DSH_HOME/.credentials.yaml`, then cwd `.env`, then `$DSH_HOME/.env`; a Unix document other users can read is refused) and fails with the TypeScript `MISSING_CREDENTIAL` sentence. Headless `pin_initial` writes the composition default as `permission/preset` / `sandbox/mode` / `approval/policy`; `/permission` switches that table; `ctx.sandboxPolicy` folds last `sandbox/mode` (omitted config `mode` is `read-only`) for bash and `write`/`edit`; `ctx.approval` `never` rejects without prompting and `ask` fails closed as `unavailable` without an answerer (the audit pair must sit in an open turn). Confining `write`/`edit`/`bash` advertise `sandbox_permissions`/`justification` and resolve a strictly-wider retry through `ctx.approval` before executing; a denied write renders `[sandbox: file access denied under <mode> mode]` plus the operation hint. Confined bash fails closed with `SANDBOX_UNAVAILABLE` when no bwrap or landlock-run backend is usable. Each wrap carries `runnerFailureRules`; a landlock runner failure needs exit 125 and a `landlock-run: ` fatal line after excluding the exact partial-enforcement notice. `dsh-sandbox-windows-acl` derives the TypeScript `workspaceWriteSid` / `tempWriteSid` and rejects overlapping temp/workspace paths; denial signatures are `access is denied` / `access to the path` / `permission denied`; Windows confinement prefixes the TypeScript Node runner (`node` plus `lib/runner.js`, or `--import tsx/esm` plus `src/runner.ts`) with the stable `--workspace` / `--temp` / `--mode` argv contract; this crate does not call CreateRestrictedToken; Wine and Linux cannot prove NTFS/DACL. Foreground runner failure throws `SANDBOX_UNAVAILABLE` with `Runner failure: {detail}`; a settled background process stamps `runnerFailed` (not `denied`). Foreground `run` returns a structured result (nonzero exits are reported, not errored) and stamps `sandbox.denied` from the wrap's denial signatures; the bash tool renders `[sandbox: file access denied under <mode> mode]` plus the command escalation hint. Background jobs start through `ctx.shell.start` under the same confine path; `job_output` appends that marker after settlement, or the runner-failure notice. The bash and pwsh tools share the foreground/background `output` oneOf and `presentCall` / `presentResult` (terminal vs generic). `pwsh-sandbox` / `tool-pwsh` mount for real and stay disabled on non-win32 via `!!js`. The bash schema requires `command` and `description` and advertises `timeoutMs` and `workdir`. `ToolCall.call_id` is passed into `ctx.approval`. Base `tool-web` keeps `fetch: false`. Two automation stdio servers ship as profiles over the same base tree: `dsh --profile acp` serves the ACP wire (`initialize` / `authenticate` / `session/new` / `session/prompt` / `session/cancel`, `agent_message_chunk` updates, the TypeScript stop-reason mapping; stdin is read while a prompt is in flight so `session/cancel` can settle `cancelled`) and `dsh --profile jsonrpc` serves the SDK runtime protocol (`initialize` / `session/prompt` / `shutdown` with `session.event` / `session.status` / `subagent.started` / `subagent.finished` notifications and the wire-stable `deepseek-harness-sdk-runtime` identity). ACP streams `agent_message_chunk` updates while `session/prompt` waits for idle, and JSON-RPC returns the `messageId` receipt as soon as the prompt is queued then streams `session.event` / `session.status` while the agent runs; ACP reads later frames while that prompt task runs; a three-end fixture holds the headless, ACP, and JSON-RPC projections of one replayed task to a single event stream. JavaScript workflow workers, packed SQLite schema 17, raster image normalization (with ACP image prompts), and host-native skill directory watching are not mounted. Headless `dsh --resume <id>` loads that persisted JSONL, appends `session/end-seed` when the stored log does not already end with one, continues turn numbering, and logs `request/header` reason `resume` on the first request of the new loop instance. Headless mounts `session-telemetry-otel` as an OTLP/HTTP JSON log exporter in `FULL` and `FEEDBACK_ONLY` (a 429/502/503/504 or transport error retries inside `processor.exportTimeoutMillis`, each HTTP attempt capped by `exporter.timeoutMillis`, honoring `Retry-After` delay-seconds and HTTP-date on HTTP and HTTPS, passing `exporter.keepAlive` (default true; HTTP/1.1 socket reuse; HTTPS one-shot `curl` cannot reuse a TLS socket), or exponential backoff, then drops the batch; a full queue drops the newest record; the seam flush hint is unimplemented and the crate emits no SDK metrics); the default `DISABLED` mode discloses sharing and constructs no exporter.

Crate names are `dsh-<pkg>`; directories mirror `packages/<group>/<pkg>/`.

```sh
cargo test --workspace
cargo run -p dsh -- --dump-config
cargo run -p dsh -- --profile headless "reply with the word pong"
```
