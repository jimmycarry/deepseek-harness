# DeepSeek Harness — Rust 移植

[English](README.md) | 中文

TypeScript harness 的语义 1:1 移植。`packages/` 下的 TypeScript 树仍是行为真源。本工作区保留插件树、能力 seam 与会话日志约定。组合身份是 TypeScript 行 `id` 加插件 `name`；`dsh --dump-config` 打印这棵组合树。跑任务会挂载同一棵树；`!!js` 只在挂载时求值。会话 JSONL 以 TypeScript 的 header 行开头，每个事件——typed 与 Extension 一样——序列化为 `{type, seq, time, data}` 并带 `sourceEventSeqs` 引用；消息携带 `role` 与 UUID `id`，并保留 TypeScript 的 `StreamChunk` 标签。会话标题真实运行：确定性回退加 first-prompt LLM provider，后者在辅助调用之前记录 `session/title-llm-request`。Headless 会挂上 `bash-sandbox`、`job_output` / `job_list` / `job_kill`（`ctx.jobs`；bash `run_in_background` 与一次性子代理后台返回 `started background job <id>`）、`glob` / `grep`（经 `ctx.subprocess` 拉起 ripgrep）、`str_replace_editor`、`create_goal` / `get_goal` / `update_goal`、continuable 后台 `subagent`（委托要求 `ctx.sessionPersistence` 并返回持久子 id；调用方预留的 id 若已被 live catalog 或 persistence 占用则拒绝；`send_message` / `interrupt_agent` / `list_agents` 按 id 寻址（`send_message` 从 persistence 冷加载不在 live catalog 的子会话，`list_agents` 则 inspect 该子会话（只读，不 `commitRepair`）并把读不到的报告为 `[diagnostic: corrupt|unavailable]` 而不是静默丢弃；persistence 的 `list_snapshots` / `read_stored_revision` 暴露后端自有的 revision token——JSONL 用 TypeScript 的文件 stat 身份，SQLite 用事件条数加 header digest，`inspect` 会共享同 id 的 in-flight 读取、在 token 变化时重试，并保留 `preparedSessionCacheSize`（默认 5）的 ready LRU；write-behind（`writeBatchMaxDelayMs`，默认 200）提供 `create` / `append` / `prepare` / `readFrom`；`load` 做耐久 `commitRepair`（JSONL 截到最后一个完整换行；SQLite 从第一个坏 seq 起 `DELETE`）；`inspect` 仍在内存中合成 closer；`list` / `list_snapshots` 仍直接读后端），子作用域的 `report` 把选定内容转交直接父级，settlement 通知携带子代理结局与收尾消息唤醒父级；进程内启动会捕获父级的显式沙箱覆盖并把审批钉成 `never`，以 `source: "delegation"` 事件写入子日志，冷恢复只重放这些事件）加一次性 `subagent_fork`、`workflow`（`return <json>`）、`ralph`（把 TypeScript 的固定 fresh-agent 循环用 Rust 跑在 `spawn` 上；不是 JavaScript worker）、`/feedback`（`recordInput: false`；日志态 `command/run` / `feedback/record` / `command/done`；确认句引用 `$DSH_HOME/.anonymous-user-id` 与可选的 `ctx.sessionTelemetry` 共享句）、`fs-observation-policy`（按 session 记录 `fs/observed`；`write` / `edit` / `str_replace_editor` 走 `createIfAbsent` 或 `replaceIfVersion`，未观察的覆盖按 TypeScript `FS_NOT_OBSERVED` 文句拒绝并附带 “read the file, then retry”）、`web_search`（DeepSeek official 或 `replay` 夹具）、`repeat-tool-reminder`、`ctx.attachments`（`save_image` 魔数准入，加上 `request_image` 在 `normalizedImageMaxDimension` / `normalizedImageMaxBytes` 下的 JPEG 归一化）、`ctx.sessionQuery`（`openAt: never`）、spill（`ctx.spillStore` 加 `spill-policy`）、`todo_write`（日志态 `todo/write`）、工具调用超时策略（按工具声明的 `timeout_ms`，`TOOL_TIMEOUT` 失败文案）、压缩期工具结果裁剪器（`compaction/prune` 加 `tool/result` replace）、plan mode（`plan/mode`、`exit_plan_mode`、`/plan`；headless 默认无 user-questions provider，plan 评审按精确文句失败；Config `reviewProvider: "auto"` 挂载选取第一项的 approver）、skill 栈（`SKILL.md` 发现、`skill` 工具、首次 `skill-catalog` 消息，以及 catalog digest 变化时带 `update: true` 的替换）、`ctx.tokenMeter`、settings-file（`debounceMs` 之后重载 `$DSH_HOME/settings.yaml`；现场非法编辑保留上一份可用文档；`register` / `watch` / `revision` / `mutate` 以及 `update` / `replace` 把已注册 namespace 以保留注释的 YAML 叶级 diff 写回；写入发出 `settings/updated` 与 `settings/document-updated`）、`ctx.shellEnv`（向模型 bash 注入受信任的 `DSH_HOME` / `DSH_SHELL=1` / `DSH_SESSION_ID`）、压缩（`llm-deepseek` 的 `defaultContextWindow` 与每模型 catalog，默认 1,000,000；按 `ctx.llm.resolve_model_info().context.contextWindow` 做 `thresholdRatio` / `retainRatio` 压力判断，按精确 `modelPolicies` 覆盖，保留切分向头部回退以免拆开 tool-call/result 对，压力重试受 `compactionRetries` 限制，溢出恢复只在会话 surface 发生替换之后才重试并止于 `maxOverflowRetries`，经 `ctx.llm.stream()` 且 `purpose: "compaction"` 使用 TypeScript 指令与多块检查点框架，成帧检查点必须小于被遮蔽区间，携带 `compactionId` 的 `compaction/start` / `summary` / `end` 且 summary 带 `provider` / `model` / `rawOutput` / `llmStreamCall`，以及经 `commands.execute` 并引用 `command/done.sourceEventSeq` 的 `/compact`）、`agent-instructions`（首次把 `AGENTS.md` / `CLAUDE.md` 与 `$DSH_HOME/AGENTS.md` 基线发布为带 `<system-reminder>` 的 `user/message`，`source.kind: agent-instructions`；这些文件随后变化时再发非基线更新）、`session-checkpoint-policy`（每次模型请求与顶层工具分派前刷盘；缺 persistence 后端视为成功空操作；JSONL 在 dispose 时排空 live session）、`ctx.sessionProjections`（缺该服务时 `list_agents` 按 TypeScript 精确文句失败），以及 `llm-retry`（无 Config；`retryPolicy` 在各 provider 上并拷到 `agent/request-error`；等待前先写 `llm/retry` 再写 `llm/retry-started`；有效且为正的 `providerRetryAfterMs` 不超过 `maxDelayMs` 时替换本地退避，超出上限时 `normal` 继续委托、`always` 改用本地退避）。`llm-deepseek` 以 `"stream": true` 和 `stream_options.include_usage` 流式传输；缺少 `[DONE]` 为 `STREAM_CLOSED`；vision 模型（`model` 含 `vision`）把用户图像做成 `image_url` data-URL。Files API 上传未挂载。`llm-deepseek` 按 TypeScript 的状态与提供方详细信息 code 分类非 2xx 响应，并保留 HTTP 状态、有效且为正的 `Retry-After` delay-seconds 或 HTTP-date，以及 `x-request-id` / `x-deepseek-request-id`。`llm-deepseek` 经 `ctx.credentials` 解析 `DEEPSEEK_API_KEY`（先继承环境，再 `$DSH_HOME/.credentials.yaml`，再 cwd `.env`，再 `$DSH_HOME/.env`；Unix 上其他用户可读的文档拒读），并以 TypeScript 的 `MISSING_CREDENTIAL` 文句失败。Headless `pin_initial` 按组合默认值写入 `permission/preset` / `sandbox/mode` / `approval/policy`；`/permission` 切换该表；`ctx.sandboxPolicy` 折叠最后一条 `sandbox/mode`（省略的配置 `mode` 为 `read-only`）供 bash 与 `write`/`edit` 使用；`ctx.approval` 的 `never` 不提示即拒绝，`ask` 在无 answerer 时以 `unavailable` 失败闭合（审计对必须落在打开的 turn 内）。施加围栏的 `write`/`edit`/`bash` 会公开 `sandbox_permissions`/`justification`，并在执行前经 `ctx.approval` 解析严格更宽的重试；被拒绝的 write 渲染 `[sandbox: file access denied under <mode> mode]` 加 operation 提示。受限制的 bash 在没有可用的 bwrap 或 landlock-run 后端时以 `SANDBOX_UNAVAILABLE` 拒载，禁止无隔离执行。每次包装都携带 `runnerFailureRules`；landlock 的 runner 失败需要退出码 125，且在排除整行精确匹配的部分强制执行通知后仍有一行 `landlock-run: ` 致命诊断。`dsh-sandbox-windows-acl` 按 TypeScript 派生 `workspaceWriteSid` / `tempWriteSid`，并拒绝重叠的 temp/workspace 路径；拒绝方言是 `access is denied` / `access to the path` / `permission denied`；Windows 围栏把 TypeScript Node runner（`node` 加 `lib/runner.js`，或 `--import tsx/esm` 加 `src/runner.ts`）按稳定的 `--workspace` / `--temp` / `--mode` argv 约定加到命令前；本 crate 不调用 CreateRestrictedToken；Wine 与 Linux 不能证明 NTFS/DACL。前台 runner 失败抛出带 `Runner failure: {detail}` 的 `SANDBOX_UNAVAILABLE`；已结算的后台进程标记 `runnerFailed`（不是 `denied`）。前台 `run` 返回结构化结果（非零退出按结果报告，不是错误），并根据 confine 返回的 denial signatures 附上 `sandbox.denied`；bash 工具渲染 `[sandbox: file access denied under <mode> mode]` 与 command 升权提示。后台 job 经 `ctx.shell.start` 走同一条 confine 路径；`job_output` 在结算后附上该标记，或附上 runner 失败通知。bash 与 pwsh 工具共享前台/后台 `output` oneOf 以及 `presentCall` / `presentResult`（terminal 与 generic）。`pwsh-sandbox` / `tool-pwsh` 真实挂载，并在非 win32 上由 `!!js` 保持禁用。bash schema 要求 `command` 与 `description`，并公开 `timeoutMs` 与 `workdir`。`ToolCall.call_id` 会传入 `ctx.approval`。base 的 `tool-web` 保持 `fetch: false`。两个自动化 stdio 服务器以 profile 形式落在同一棵 base 树上：`dsh --profile acp` 提供 ACP 线上协议（`initialize` 仅在挂了 `ctx.attachments` 且 `AgentDefaultModel` 为 vision 时广告 `image: true`；`authenticate` / `session/new` / `session/prompt` / `session/cancel`、`agent_message_chunk` 更新、TypeScript 的 stop-reason 映射；prompt 进行中仍读 stdin，因此 `session/cancel` 能以 `cancelled` 结算），`dsh --profile jsonrpc` 提供 SDK 运行时协议（`initialize` / `session/prompt` / `shutdown`，`session.event` / `session.status` / `subagent.started` / `subagent.finished` 通知，线上稳定身份 `deepseek-harness-sdk-runtime`）。ACP 在 `session/prompt` 等待 idle 期间流出 `agent_message_chunk` 更新，JSON-RPC 在提示词入队后立即返回 `messageId` 回执并在 agent 运行时流出 `session.event` / `session.status`；ACP 还会在该 prompt 任务进行中读取后续帧；一个三端 fixture 把同一 replay 任务在 headless、ACP、JSON-RPC 三端的投影钉在同一条事件流上。JavaScript workflow worker、打包的 SQLite schema 17、DeepSeek Files API 上传、宿主原生 skill 目录监听未挂载。Headless `dsh --resume <id>` 会加载该持久化 JSONL，在存储日志尚未以 `session/end-seed` 结尾时补上该事件，继续 turn 编号，并在新 loop 实例的第一次请求上记录 `request/header` reason `resume`。Headless 挂载 `session-telemetry-otel`：`FULL` 与 `FEEDBACK_ONLY` 导出 OTLP/HTTP JSON 日志（429/502/503/504 或传输错误在 `processor.exportTimeoutMillis` 内重试，单次 HTTP 受 `exporter.timeoutMillis` 限制，遵守 HTTP 与 HTTPS 上的 `Retry-After` delay-seconds 与 HTTP-date，透传 `exporter.keepAlive`（默认 true；HTTP/1.1 复用套接字；HTTPS 的一次性 `curl` 不能复用 TLS 套接字），或指数退避，然后丢弃该批；队列满则丢弃最新记录；seam 的 flush 提示未实现，crate 不发出 SDK metrics）；默认 `DISABLED` 只披露 sharing、不构造 exporter。

crate 名为 `dsh-<pkg>`；目录对齐 `packages/<group>/<pkg>/`。

```sh
cargo test --workspace
cargo run -p dsh -- --dump-config
cargo run -p dsh -- --profile headless "reply with the word pong"
```
