# DeepSeek Harness — Rust 移植

[English](README.md) | 中文

TypeScript harness 的语义 1:1 移植。`packages/` 下的 TypeScript 树仍是行为真源。本工作区保留插件树、能力 seam 与会话日志约定。组合身份是 TypeScript 行 `id` 加插件 `name`；`dsh --dump-config` 打印这棵组合树。跑任务会挂载同一棵树；`!!js` 只在挂载时求值。会话 JSONL 以 TypeScript 的 header 行开头，每个事件——typed 与 Extension 一样——序列化为 `{type, seq, time, data}` 并带 `sourceEventSeqs` 引用；消息携带 `role` 与 UUID `id`，并保留 TypeScript 的 `StreamChunk` 标签。会话标题真实运行：确定性回退加 first-prompt LLM provider，后者在辅助调用之前记录 `session/title-llm-request`。Headless 会挂上 `bash-sandbox`、`job_output` / `job_list` / `job_kill`（`ctx.jobs`；bash `run_in_background` 与一次性子代理后台返回 `started background job <id>`）、`glob` / `grep`（经 `ctx.subprocess` 拉起 ripgrep）、`str_replace_editor`、`create_goal` / `get_goal` / `update_goal`、continuable 后台 `subagent`（委托返回持久子 id；`send_message` / `interrupt_agent` / `list_agents` 按 id 寻址，子作用域的 `report` 把选定内容转交直接父级，settlement 通知携带子代理结局与收尾消息唤醒父级）加一次性 `subagent_fork`、`workflow`（`return <json>`）、`ralph`（把 TypeScript 的固定 fresh-agent 循环用 Rust 跑在 `spawn` 上；不是 JavaScript worker）、`/feedback`（`recordInput: false`；日志态 `command/run` / `feedback/record` / `command/done`；确认句引用 `$DSH_HOME/.anonymous-user-id` 与可选的 `ctx.sessionTelemetry` 共享句）、`fs-observation-policy`（按 session 记录 `fs/observed`；`write` / `edit` / `str_replace_editor` 走 `createIfAbsent` 或 `replaceIfVersion`，未观察的覆盖按 TypeScript `FS_NOT_OBSERVED` 文句拒绝并附带 “read the file, then retry”）、`web_search`（DeepSeek official 或 `replay` 夹具）、`repeat-tool-reminder`、`ctx.attachments`、`ctx.sessionQuery`（`openAt: never`）、spill（`ctx.spillStore` 加 `spill-policy`）、`todo_write`（日志态 `todo/write`）、工具调用超时策略（按工具声明的 `timeout_ms`，`TOOL_TIMEOUT` 失败文案）、压缩期工具结果裁剪器（`compaction/prune` 加 `tool/result` replace）、plan mode（`plan/mode`、`exit_plan_mode`、`/plan`；headless 无 user-questions provider，plan 评审按精确文句失败）、skill 栈（`SKILL.md` 发现、`skill` 工具、首次 `skill-catalog` 消息，以及 catalog digest 变化时带 `update: true` 的替换）、`ctx.tokenMeter`、settings-file（`debounceMs` 之后重载 `$DSH_HOME/settings.yaml`；现场非法编辑保留上一份可用文档）、压缩（按已记录的 `request/context.contextWindow` 做 `thresholdRatio` / `retainRatio` 压力判断，携带 `compactionId` 的 `compaction/start` / `summary` / `end`，以及经 `commands.execute` 的 `/compact`）、`agent-instructions`（首次把 `AGENTS.md` / `CLAUDE.md` 与 `$DSH_HOME/AGENTS.md` 基线发布为带 `<system-reminder>` 的 `user/message`，`source.kind: agent-instructions`；这些文件随后变化时再发非基线更新）、`session-checkpoint-policy`（每次模型请求与顶层工具分派前刷盘；缺 persistence 后端视为成功空操作）、`ctx.sessionProjections`（缺该服务时 `list_agents` 按 TypeScript 精确文句失败），以及 `llm-retry`（无 Config；`retryPolicy` 在各 provider 上；等待前先写 `llm/retry` 再写 `llm/retry-started`）。受限制的 bash 在没有可用的 bwrap 或 landlock-run 后端时以 `SANDBOX_UNAVAILABLE` 拒载，禁止无隔离执行。base 的 `tool-web` 保持 `fetch: false`。两个自动化 stdio 服务器以 profile 形式落在同一棵 base 树上：`dsh --profile acp` 提供 ACP 线上协议（`initialize` / `authenticate` / `session/new` / `session/prompt` / `session/cancel`、`agent_message_chunk` 更新、TypeScript 的 stop-reason 映射），`dsh --profile jsonrpc` 提供 SDK 运行时协议（`initialize` / `session/prompt` / `shutdown`，`session.event` / `session.status` / `subagent.started` / `subagent.finished` 通知，线上稳定身份 `deepseek-harness-sdk-runtime`）。两者都在请求内把 turn 驱动到静止，因此通知在响应之前落在同一条有序流上；一个三端 fixture 把同一 replay 任务在 headless、ACP、JSON-RPC 三端的投影钉在同一条事件流上。JavaScript workflow worker、打包的 SQLite schema 17、栅格图像归一化（含 ACP 图像提示）、LLM 压缩摘要、宿主原生 skill 目录监听未挂载。

crate 名为 `dsh-<pkg>`；目录对齐 `packages/<group>/<pkg>/`。

```sh
cargo test --workspace
cargo run -p dsh -- --dump-config
cargo run -p dsh -- --profile headless "reply with the word pong"
```
